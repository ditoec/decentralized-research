# trajescrow: escrow program for RQ3 (WP5)

Solana Anchor program for the escrow substrate of runbook `docs/07-runbook.md` §7 item 1, with
its TypeScript client, the state-machine tests and the path replay of §7 item 3.
Program id (localnet): `HmMX8b7GLwUeJv4dw42xHAryRVfQm319ArWNbfj9ePpf`. The program keypair is not
in the repository; the operator's Mac keeps it in `target/deploy/` (git-ignored). Deploying to Devnet with
that keypair keeps the same id and the same binary (`program_so_sha256` of the local run). Without it, generate
a new keypair, run `anchor keys sync` and rebuild. Mainnet is never used.

## Accounts

- `Config` (PDA `"config"`): admin, orchestrator key, SPL mint, treasury, p (`sample_ppm`, parts per
  million), `draw_delay` (DELAY, in slots), `exec_timeout`, `dispute_timeout`, the registered verifier pool (≤ 8).
- Treasury (PDA `"treasury"`): SPL token account that receives slashed bonds.
- `Job` (PDA `"job" ‖ job_id as u64 LE`): parties, P, verifier fee, B, the snapshot of p, deadlines,
  the commitment (Merkle root, output digest, commit slot), the draw (slot used, seed, sampled), both
  verifiers' commitments and verdicts, and the `slashed` and `settled` flags.
- Escrow vault (PDA `"vault" ‖ job`): SPL token account that holds P plus the verifier fee. It is closed at settlement and its rent goes back to the requester.
- `ProviderBond` (PDA `"bond" ‖ provider`) with its bond vault (PDA `"bond_vault" ‖ provider`).
  The provider deposits once. `accept_job` locks B of the free balance without moving any tokens,
  settlement unlocks it, and `slash` moves B to the treasury.

## State machine (runbook §7 item 1, one to one)

| From | Event | To | Funds | Test (`tests/trajescrow.ts`) |
|---|---|---|---|---|
| — | `create_job` | Funded | P + fee into the vault | "create_job → Funded" |
| Funded | `accept_job` | Assigned | B locked in `ProviderBond` | "Funded → accept_job" |
| Funded | `refund` signed by the requester | Closed-refunded | P + fee returned | "Funded → requester cancels" |
| Assigned | `commit_result` | Committed | — | "Assigned → commit_result" |
| Assigned | `timeout_refund` after `exec_deadline` | Closed-refunded | P + fee returned, B unlocked | "Assigned → deadline passes" |
| Committed | `draw_sample`, not sampled | Closed-paid, then `release` | P to provider, B unlocked, fee back to the requester | "draw_sample, not sampled" |
| Committed | `draw_sample`, sampled | UnderVerification | — | "draw_sample, sampled" |
| UnderVerification | `submit_verdict` = pass | Closed-paid, then `release` | P to provider, B unlocked, fee to the verifier | "submit_verdict = pass" |
| UnderVerification | `submit_verdict` = fail / inconclusive | Disputed | — | "fail or inconclusive → Disputed" |
| Disputed | `escalate`, then `final_verdict` = pass | Closed-paid, then `release` | as for pass (fee split between both verifiers) | "second verifier agrees" |
| Disputed | `final_verdict` = fail after a first fail | Closed-refunded (slashed), then `slash` | P to requester, B to the treasury | "both verifiers against" |
| Disputed | no two-of-three majority | Closed-unresolved, then `refund` | P to requester, B unlocked | "all three disagree" |
| any open state | `timeout_refund` after `final_deadline` | Closed-refunded | P to requester, B unlocked | "any open state → timeout_refund" |

Further tests cover the guards: a node never verifies its own job (`SelfVerification`), the draw
before `commit_slot + DELAY` fails (`DrawTooEarly`), the second verifier must differ from the
first, a verifier must commit before it reveals, unregistered verifiers are rejected, only the
provider, the requester or the orchestrator may escalate, and only the free bond balance can be
withdrawn. Rust unit tests (`cargo test --lib` in `programs/trajescrow`) cover the SlotHashes
lookup and the bounds p = 0 and p = 1.

### The draw

`draw_sample` can be called by anyone once `slot > commit_slot + DELAY`. It reads the `SlotHashes`
sysvar account directly (parsing it by hand, with a binary search) and takes the entry for
`target = commit_slot + DELAY`. If that slot was skipped, it takes the first produced slot after
the target. Every caller gets the same entry, because entries older than the current slot do not
change. If the window of about 512 slots has moved past the target, the call fails with
`SlotHashExpired` and the job can only be closed by `timeout_refund`.
`draw_seed = SHA-256(slot_hash ‖ job_id_u64_le)`. The job is sampled iff
`floor(u · 10⁶ / 2⁶⁴) < sample_ppm`, where `u` is the first 8 bytes of the seed read as little-endian.
The verifier derives the checked steps from `draw_seed`, for example with
`trajver.retention.step_order(draw_seed, job_key, T)`.

### Choices the runbook table leaves open

They are recorded here so the paper text can state them.

1. **Verifier fee.** It goes to the verifier(s) who revealed a verdict. If both did, it is split
   evenly and the odd unit goes to the first. If no verdict was revealed (unsampled, cancel,
   execution timeout), it goes back to the requester. The table names the fee only for the pass row.
2. **Two-of-three.** The three positions are the provider's claim (pass), verifier 1 and verifier 2.
   The bond is slashed only on two `fail` verdicts. Every other combination without a second `pass`
   (fail + inconclusive, inconclusive + fail, inconclusive + inconclusive) is Closed-unresolved, with no penalty.
3. **`escalate`** marks the dispute for a second verifier and leaves the state at Disputed. The
   provider, the requester or the orchestrator may call it. If nobody escalates, the job is
   refunded at the dispute deadline with the bond returned.
4. **Commit, then verdict.** `submit_verdict` and `final_verdict` each take two calls: `Commit {
   commitment }` records the verifier's commitment to its own recomputed values, and `Reveal {
   verdict }` comes in a later transaction. The program enforces the order but cannot check what the
   commitment hashes. That check happens off chain, in a dispute.
5. **Verifier eligibility.** Any key in `Config.verifiers` other than the job's provider or requester
   can act as verifier 1, first come first served. The orchestrator assigns verifiers off chain.
   Verifier 2 must also differ from verifier 1.
6. **Settlement is a separate, permissionless instruction** (`release` / `refund` / `slash`) after the
   transition that decides the outcome. `timeout_refund` and the requester's cancel decide and settle in one call.
7. **Deadlines.** `exec_deadline = accept_slot + exec_timeout`. `final_deadline = exec_deadline +
   dispute_timeout`. For a job that is still Funded, `final_deadline = create_slot + exec_timeout + dispute_timeout`.
8. p, DELAY and the timeouts are copied from `Config` into each job at `create_job` (p) and at
   `accept_job` (the deadlines). This lets a replay force a path by changing `Config` between jobs.

No ground-truth attack label reaches the program. Disputes are decided only from the two recorded verdicts.

## Build and test (Mac, Anchor 1.2.2, Solana CLI 4.x, platform-tools v1.57)

```bash
cd code/program && npm ci
./scripts/build.sh                                # the workaround build, then the IDL build
anchor test --skip-build --validator legacy       # solana-test-validator; the Anchor 1.x default is surfpool
```

The build needs a workaround because `anchor build` on its own fails with this toolchain.
`build.sh` runs `anchor build --no-idl -- --no-rustup-override` with
`~/.cache/solana/v1.57/platform-tools/rust/bin` first on `PATH`, so the workspace
`rust-toolchain.toml` (1.89) does not override the SBF toolchain. It then runs
`anchor idl build` with the host toolchain.

## Path replay (runbook §7 item 3, local validator)

```bash
./scripts/local-validator.sh &                    # fresh ledger, program preloaded
npx ts-node -P tsconfig.json scripts/replay.ts --n 100
```

The four paths are interleaved in a shuffled order each round. Before each job a `Config` update
(not counted) forces p = 0 (unsampled) or p = 1 (the other paths). The replay writes
`experiments/runs/<date>-wp5-escrow-replay-local-NN/` with `manifest.json`, `summary.json` (per path:
transactions, signatures, compute units and fees per job, and CU per instruction) and `txs.jsonl`
(one row per transaction with its signature). With `--cluster localnet` (the default) the script refuses
any URL that is not a local validator.

## Path replay on Devnet

`--cluster devnet` uses `https://api.devnet.solana.com` and no other URL. Any URL containing "mainnet",
and any RPC that reports Mainnet's genesis hash, is a hard error. The script airdrops nothing on Devnet.
The `--admin` keypair must already hold Devnet SOL, and the script funds five throwaway actor keypairs
from it by transfer (saved, git-ignored, as `.anchor/devnet/actors-<run>.json`). On Devnet the deadlines
are `exec_timeout` 150 slots and `dispute_timeout` 600 slots, and the timeout path keeps
`exec_timeout` = 2 slots, so it waits for a real deadline. The program is unchanged. The run folder is
`experiments/runs/<date>-wp5-devnet-replay-NN/`, and `summary.json` also gives the per-transaction
confirm-time median and p95 and the mean CU.

```bash
export PATH="$HOME/.cargo/bin:$HOME/.local/share/solana/install/active_release/bin:$PATH"
solana-keygen new --no-bip39-passphrase -o .anchor/devnet/keypair-payer.json   # git-ignored
# fund it with Devnet SOL (see below), then deploy the same binary as the local run:
solana program deploy -u devnet -k .anchor/devnet/keypair-payer.json \
  --program-id target/deploy/trajescrow-keypair.json target/deploy/trajescrow.so
npx ts-node -P tsconfig.json scripts/replay.ts --cluster devnet --admin .anchor/devnet/keypair-payer.json --n 100
```

On the public RPC the replay spaces its requests, confirms by polling `getSignatureStatuses` (the websocket is
rate-limited), counts 429s per transaction (`rpc_429`), retries dropped connections, keeps failed jobs in
`jobs.jsonl` with their error, and starts job ids at a time-based base (Job PDAs persist on Devnet). If some
paths end short of their target, run a top-up and combine:

```bash
npx ts-node -P tsconfig.json scripts/replay.ts --cluster devnet --admin .anchor/devnet/keypair-payer.json \
  --only dispute=10,timeout=3 --topup-of <main-run-id> --seed 2   # counts = successful jobs still needed
python3 scripts/combine_replay.py ../../experiments/runs/<main-run> ../../experiments/runs/<top-up-run>
```

Funding: since 2026-11-26 the Devnet RPC faucet (`solana airdrop`) answers

The calculated mainnet fee per path is a later step.
